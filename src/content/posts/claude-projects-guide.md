AI 챗봇으로 같은 업무를 반복하다 보면 대화를 새로 열 때마다 "우리 회사는 이런 곳이고, 이 문서를 참고해서, 이런 말투로…"를 다시 설명하게 됩니다. **Claude의 프로젝트(Projects)** 는 이 설명과 자료를 한 곳에 넣어 두고, 그 안에서 여는 모든 대화가 자동으로 참고하게 하는 기능입니다.

이 글은 Anthropic의 Claude 고객센터 공식 도움말을 바탕으로 웹(claude.ai) 기준으로 정리했습니다. 도움말이 영어로 제공되므로 메뉴 이름은 **영어 화면 기준** 으로 적었습니다. 한국어 화면에서는 표시가 다를 수 있습니다. (작성일 2026년 10월 31일)

## 프로젝트가 뭔가요

공식 도움말은 프로젝트를 "자체 대화 기록과 지식 베이스를 가진 독립된 작업 공간"이라고 설명합니다.

| 구성 요소 | 역할 |
|---|---|
| **프로젝트 지식(Project knowledge)** | 문서, 텍스트, 코드 등을 올려 두면 프로젝트 안의 모든 대화가 배경 자료로 사용 |
| **프로젝트 지침(Project instructions)** | 말투, 역할, 관점 등 모든 대화에 적용할 지시 |
| **대화 기록** | 프로젝트 안에서 나눈 대화만 모아서 보관 |

### 누가 쓸 수 있나

| 요금제 | 내용 |
|---|---|
| 무료 | 사용 가능, **최대 5개** 프로젝트 |
| 유료 | 지식이 많아 컨텍스트 한도에 가까워지면 **RAG 모드** 가 자동으로 켜져 용량을 최대 약 10배까지 확장 |
| Team·Enterprise | 조직 구성원과 프로젝트 **공유** 가능 |

## 1단계: 프로젝트 만들기

1. 왼쪽 메뉴의 **Projects** 를 누르거나 claude.ai/projects 로 이동합니다.
2. 오른쪽 위 **+ New Project** 를 클릭합니다.
3. 이름과 설명을 입력합니다. 공식 도움말에 따르면 **이 이름과 설명은 Claude가 보지 않습니다.** 나중에 찾기 쉽게 적으면 됩니다.
4. Team·Enterprise 요금제라면 비공개로 둘지 조직에 공유할지 고릅니다.

## 2단계: 프로젝트 지식에 자료 올리기

1. 프로젝트 화면 오른쪽 **프로젝트 지식** 영역의 **+** 버튼을 클릭합니다.
2. 문서, 텍스트 파일, 코드 등을 올립니다.
3. 이후 프로젝트 안의 대화에서 Claude가 이 자료를 참고합니다.

### 무엇을 올리면 좋나

| 업무 | 올릴 자료 예 |
|---|---|
| 고객 문의 답변 | 자주 묻는 질문 모음, 환불 규정, 제품 설명서 |
| 보고서 작성 | 지난 보고서 2~3편, 회사 문서 양식 |
| 블로그·마케팅 글 | 브랜드 말투 가이드, 금지 표현 목록, 잘 된 글 예시 |
| 공부 | 강의 노트, 교재 요약 |

> 회사 내부 문서를 올리기 전에는 회사 보안 규정을 먼저 확인하세요. 고객 개인정보가 들어 있는 파일은 올리지 않는 것이 안전합니다.

## 3단계: 프로젝트 지침 설정하기

1. 프로젝트 화면에서 **Set project instructions** 를 클릭합니다.
2. 지침을 입력하고 **Save instructions** 를 클릭합니다.
3. 이 지침은 프로젝트 안의 **모든 대화** 에 적용됩니다.

### 지침 예시: 고객 문의 답변 프로젝트

```text
너는 온라인 쇼핑몰의 고객지원 담당자야.
- 답변은 존댓말로, 5문장 이내로 써.
- 환불·교환 내용은 반드시 프로젝트 지식의 '환불 규정' 문서에 있는 내용만 안내해.
- 문서에 없는 내용은 추측하지 말고 "담당 부서 확인 후 안내드리겠습니다"라고 답해.
- 고객이 화가 나 있으면 먼저 불편에 대해 사과하는 문장으로 시작해.
```

### 지침 예시: 주간 보고서 프로젝트

```text
팀장님께 올리는 주간 업무 보고서를 작성하는 프로젝트야.
- 형식은 프로젝트 지식의 '보고서 양식' 파일을 그대로 따라.
- 내가 메모를 붙여 넣으면 '완료 / 진행 중 / 다음 주 계획'으로 나눠 정리해.
- 숫자는 내가 준 값만 쓰고 계산이 필요하면 계산 과정을 따로 보여줘.
```

지침은 짧은 문장의 목록으로 쓰고, "추측하지 말 것"처럼 **하지 말아야 할 일** 을 함께 적으면 결과가 안정적입니다. 프롬프트 작성 원칙은 [AI 프롬프트 잘 쓰는 법](/posts/ai-prompt-writing-guide/)에 정리했습니다.

## 프로젝트 안에서 대화하기

프로젝트를 열고 대화를 시작하면 지식과 지침이 자동으로 적용됩니다. 한 가지 주의할 점이 있습니다.

> 공식 도움말: 프로젝트 안의 대화끼리는 **맥락이 공유되지 않습니다.** 다른 대화에서도 써야 하는 정보는 프로젝트 지식에 넣어야 합니다.

예를 들어 한 대화에서 "이번 분기 목표는 매출 10% 증가야"라고 말했더라도, 다른 대화는 이를 모릅니다. 계속 쓸 정보라면 텍스트로 정리해 프로젝트 지식에 추가하세요.

### 프로젝트별 메모리

공식 도움말에 따르면 각 프로젝트는 **자체 메모리** 를 가집니다. 계정 전체 메모리와 분리하고 싶다면 프로젝트 화면의 Memory 항목에서 **Use account memory** 를 끄면 됩니다.

## 기존 대화를 프로젝트로 옮기기

1. 옮길 대화를 열고 대화 이름 옆 드롭다운 화살표를 클릭합니다.
2. **Add to project** 를 선택합니다.
3. **Move chat** 창에서 프로젝트를 클릭합니다.

다른 프로젝트로 옮기거나 빼는 것도 같은 메뉴에서 합니다.

## 보관·삭제·공유

| 하고 싶은 일 | 방법 |
|---|---|
| 보관(Archive) | 프로젝트 오른쪽 위 점 세 개 → 보관 확인. 목록 맨 아래로 이동하며 대화·지식·공유 설정은 유지 |
| 삭제 | 점 세 개 → **Delete** → **Yes, delete**. 보관된 프로젝트는 **보관 해제 후** 삭제 가능 |
| 공유 (Team·Enterprise) | 프로젝트 이름 옆 **Share project** → 이름·이메일 입력 → **Can view** 또는 **Can edit** 선택 → **Share** |

공유 권한은 두 가지입니다. **Can view** 는 내용을 보고 대화할 수 있지만 수정은 못 하고, **Can edit** 는 지침과 지식을 바꾸고 구성원을 관리할 수 있습니다. 조직 관리자는 프로젝트 공유를 끌 수 있습니다.

## 안 될 때: 자주 겪는 문제와 해결법

| 증상 | 원인 | 해결 |
|---|---|---|
| 새 프로젝트를 만들 수 없음 | 무료 요금제는 최대 5개 | 안 쓰는 프로젝트 삭제 또는 유료 요금제 |
| 다른 대화에서 한 말을 기억 못 함 | 프로젝트 안 대화끼리 맥락 미공유 | 계속 쓸 정보는 프로젝트 지식에 추가 |
| Claude가 프로젝트 이름을 모름 | 이름·설명은 Claude에게 보이지 않음 | 필요한 설명은 지침이나 지식에 작성 |
| 지침을 무시하는 것 같음 | 지침이 길고 모호함 | 짧은 목록으로 다시 쓰고 우선순위 명시 |
| 프로젝트를 삭제할 수 없음 | 보관 상태 | 보관 해제 후 삭제 |
| 공유 버튼이 없음 | 개인 요금제이거나 관리자가 공유를 끔 | Team·Enterprise에서 관리자에게 확인 |

## 정리

- 프로젝트는 **지식(자료) + 지침(말투·역할) + 대화 기록** 을 묶은 작업 공간이며, 무료 사용자는 5개까지 만들 수 있습니다.
- **Set project instructions** 에 짧은 목록으로 지침을 쓰고, 자주 쓰는 문서는 프로젝트 지식에 올립니다.
- 프로젝트 안 대화끼리는 맥락이 공유되지 않으므로, 계속 쓸 정보는 지식에 넣어 둡니다.
